12 October 2026Local findings · full recheck

What the audit establishes—and what remains unresolved

All 109 resources are present, and the main lentiMPRA population can be recovered. Independent model evaluation and numerical specificity-score reproduction still have concrete blockers.

The findings below were first recorded on 11 October. A full rerun on 12 October reproduced every non-metadata section of the audit, including file hashes, sequence overlap, table reconciliation, and code inspection. These are findings about the local copies, not new biological discoveries or a judgment on every copy of the published datasets.

The legacy “independent” test set is contaminated

The first 100 enhancer sequences in enhancer.ind.txt exactly match sequences in enhancer.cv.txt. That is 50% of the 200 test positives and 25% of all 400 test records. A model could therefore encounter the same DNA during development and testing; these files cannot currently support a sequence-independent evaluation.

Removing those 100 duplicates alone is not enough to establish independence. Related loci, near-duplicates, and reverse complements still need an explicit split policy. This finding concerns the local legacy files, not proof of leakage in every published model.

ENCODE files can count the same measurement twice

Each of the eight experiments has three replicate TSV files and one combined TSV containing those same measurements. Concatenating all 32 files creates 3,850,212 rows from 1,925,106 distinct complete rows within experiments. More rows here do not mean more experimental evidence.

Each experiment requires the combined TSV or its three replicate TSVs. Experiment, cell, replicate, construct, and source-file identity must be preserved; deduplicating unrelated experiments together would remove genuine repeat measurements.

The matched lentiMPRA population largely reconciles

The joint-library inputs are HepG2 ENCSR405QCT, K562 ENCSR203UFY, and WTC11 ENCSR336MKI. Two control-name differences have an explicit proposed mapping; confirmation against the original construct FASTA is required before assigning sequences. no_BC is a processing placeholder outside the designed-construct population.

Retaining a construct when at least one replicate has ≥10 observed barcodes in each of the three cells recovers exactly the 55,977 names in the published specificity table, with no extra or missing names. Requiring all three replicates to meet that threshold gives 55,863, a different population. Recovering the names does not reproduce the scores.

Specificity-score reproduction remains unresolved

These scores describe how much a construct favors one cellular setting. A direct reconstruction from the rounded shared means differs from the supplied scores: RMSE 0.1067 and maximum absolute difference 1.5764. We still need to trace the authors’ normalization, filtering population, replicate aggregation, and rounding before interpreting new selectivity results.

This diagnostic mismatch does not by itself show that the published values are wrong. Matching the analysis population and reproducing its numerical values are separate milestones.

All 109 downloaded resources are present

The local collection totals 51,069,049,058 bytes: 51.07 decimal GB, approximately 47.56 GiB, including the optional compressed data and model archives. The integrity checks have three different levels:

  • 55 files match reference checksums.
  • 5 files match previously reviewed publication receipts, rather than the older companion-manifest bytes.
  • 49 files match recorded sizes without an upstream checksum; newly computed local hashes identify the inspected copies but do not independently establish upstream identity.

The resources are present in the audited workspace. A fresh Git clone includes the original article PDFs, benchmark files, supplements, documentation, and website. Large datasets and publication downloads inside NEW_2026_DATA remain excluded from Git. The full AlphaGenome Atlas is not stored here.

Some code needs repair before use

The downloader’s read-only verification still rejects five accepted publication copies: four checksum mismatches and one six-byte size difference. Its paper-download path does not consult the saved receipts. Failed replacement downloads preserve existing originals, but the current command is not a fully verified way to restore those accepted versions.

The archived DNABERT prediction launcher calls run_finetune_WANDB_rekha.py, which is missing from the code ZIP. A differently named training script is present, but has not been validated as a replacement. Launcher paths, argument quoting, dependencies, and model compatibility need checking before inference. These code issues remain open.
