De los archivos originales a un análisis reproducible

El proceso comienza con los datos originales y un entorno local de Python. VS Code ofrece un espacio opcional para editar scripts y ejecutar comandos; Python realiza los cálculos. La primera tarea es reconstruir los dos clasificadores de iEnhancer-2L y documentar cuánto coinciden los resultados con los del artículo.

Se trata de reproducción computacional usando el conjunto de referencia recibido. Reconstruir el muestreo original del genoma o repetir experimentos de laboratorio es otra tarea. La reconstrucción inicial utiliza el conjunto de referencia original; los 51.07 GB de recursos nuevos no son necesarios en esta etapa.

Paso 01 / Herramientas

Preparar un espacio de investigación sencillo

VS Code + extensión Python de Microsoft
Un espacio opcional para editar scripts y revisar resultados. La terminal integrada se abre mediante Terminal → New Terminal; los mismos comandos funcionan también en una terminal independiente.
Python
El proceso requiere una versión de Python 3 con soporte; Python 3.13 es una opción inicial sugerida para un entorno nuevo. El script de preparación solo requiere módulos integrados y Python 3.10 o posterior. Las dependencias fijadas para extraer características requieren Python 3.12 o posterior; la ejecución local registrada utilizó Python 3.14.3.
Git
Permite obtener el repositorio y registrar la versión exacta del código de cada ejecución.
NumPy + RapidFuzz
La etapa implementada utiliza matrices numéricas y comparaciones mediante distancia de edición. Las versiones están fijadas en el repositorio. Scikit-learn o LIBSVM oficial servirán para implementar los clasificadores después. Los cuadernos Jupyter siguen siendo opcionales.
LIBSVM
El artículo utilizó LIBSVM con un núcleo RBF. La comparación entre LIBSVM oficial y SVC de scikit-learn, basado en LIBSVM, requiere igualar explícitamente la configuración; los valores predeterminados no demuestran equivalencia.

Equipo: la CPU de una computadora portátil es suficiente para comenzar; no se requiere GPU ni un servicio de nube de pago para preparar datos o iniciar la reconstrucción con SVM. Las búsquedas completas de parámetros y la evaluación dejando un ejemplo fuera pueden llevar bastante tiempo. Una comprobación pequeña y una estimación de duración preceden a la evaluación completa.

git clone --config core.autocrlf=false https://github.com/Venettov/EnhancersResearch.git

Paso 03 / Entorno

Aislar el software y registrar sus versiones

Un entorno virtual es un espacio de instalación de Python específico del proyecto. Esta es una propuesta moderna, no el entorno de software de 2015 recuperado de los autores. Los comandos requieren una instalación de Python 3.13.

macOS / Linux
python3.13 --version
python3.13 -m venv .venv
source .venv/bin/activate
python --version
python -c "import sys; print(sys.executable)"
Windows · terminal Command Prompt de VS Code
py -3.13 --version
py -3.13 -m venv .venv
.venv\Scripts\activate.bat
python --version

Estos comandos requieren el perfil Command Prompt, disponible en el menú de perfiles de terminal. No requieren cambiar la política de ejecución de PowerShell.

La acción Python: Select Interpreter de la paleta de comandos de VS Code permite establecer el intérprete que está dentro de .venv. La ruta impresa arriba debe apuntar allí. Instrucciones de entornos en VS Code · Documentación de entornos virtuales de Python.

El Paso 04 no requiere paquetes adicionales. Los comandos siguientes instalan las dependencias fijadas para los grupos y las características de los Pasos 05–06:

python -m pip install -r replication/ienhancer_2l/requirements.txt
python -m pip check

La interfaz oficial opcional de LIBSVM se instala con python -m pip install libsvm-official. Instalar paquetes e importarlos correctamente no valida el modelo. Las versiones exactas deben registrarse después de configurar el entorno, junto con cualquier cambio posterior.

Paso 04 / Ejecutable ahora

Preparar y comprobar las secuencias etiquetadas

El script de preparación compara hashes de archivos con las copias revisadas, lee FASTA, comprueba secuencias de 200 bases A/C/G/T, asocia etiquetas y mide coincidencias exactas entre prueba y entrenamiento. Conserva intactos los originales.

python replication/ienhancer_2l/prepare_data.py
python -m pip freeze > replication/ienhancer_2l/output/environment-lock.txt
git rev-parse HEAD > replication/ienhancer_2l/output/repository-commit.txt
python --version > replication/ienhancer_2l/output/python-version.txt

Comprobación esperada: 2,968 secuencias: 742 fuertes, 742 débiles y 1,484 no potenciadores. Prueba histórica: 400 registros, con 100 coincidencias exactas con entrenamiento, todas fuertes. Esto confirma únicamente la preparación de los datos.

  • benchmark.csv: secuencias, hashes, páginas de origen y etiquetas. is_enhancer vale 1 para fuerte/débil y 0 para no potenciadores. is_strong vale 1 para fuerte, 0 para débil y queda vacío para no potenciadores.
  • legacy_test_diagnostic_only.csv: la prueba histórica posterior, con una marca de solapamiento; se mantiene separada del conjunto de referencia.
  • data_audit.json: recuentos, hashes y límites. Los resultados quedan en replication/ienhancer_2l/output/, excluida de Git por defecto. Volver a ejecutar reemplaza estos archivos derivados, por lo que cada ejecución debe archivarse antes de cambiar los datos de entrada.
Si un comando falla

Python no encontrado: es necesario instalar el intérprete seleccionado y volver a abrir la terminal. Archivo no encontrado: el comando requiere la raíz del repositorio como directorio de trabajo y la presencia de los datos versionados. Hash o etiqueta diferentes: el proceso debe detenerse para comparar con los originales guardados en Git; cambiar los hashes esperados para eludir la comprobación la invalidaría. Error de importación posterior: VS Code y pip deben usar el mismo entorno.

Paso 05 / Diseño de evaluación

Definir qué significará cada resultado antes de entrenar

Una partición es una parte de los datos que se reserva mientras el modelo aprende del resto. En la validación anidada, las particiones internas seleccionan parámetros y las externas estiman el rendimiento con ejemplos no usados en esa selección.

Vía A: reconstrucción histórica. Esta vía utiliza los 2,968 ejemplos de S1 para identificar potenciadores y sus 1,484 potenciadores para clasificar fuerza. El artículo seleccionó parámetros de características mediante validación cruzada de 5 particiones y después presentó resultados jackknife (dejando un ejemplo fuera). Una evaluación con parámetros fijos requiere 2,968 + 1,484 ajustes; la búsqueda de parámetros añade más. Una prueba rápida de 5 particiones sirve para depurar, no reproduce el resultado jackknife.

Vía B: una nueva evaluación por grupos. Los 2,968 intervalos se verificaron contra hg19, con coordenadas que comienzan en cero y excluyen el extremo final. Se conectan registros cuyas regiones se solapan o están separadas por un máximo de 1,000 bases en el mismo cromosoma, o cuyas secuencias de 200 bases difieren en un máximo de 40 ediciones globales en cualquiera de las dos orientaciones. Los grupos conectados permanecen juntos en 5 particiones externas y 3 internas, con semilla 42 y equilibrio entre las tres clases. Son decisiones del proyecto, no el procedimiento de dejar uno fuera del artículo ni la regla de identidad de CD-HIT. Reducen riesgos concretos de fuga de información, sin demostrar independencia completa. La política, las asignaciones y las comprobaciones están guardadas antes del entrenamiento. Cualquier escalador o búsqueda de parámetros debe utilizar solo las particiones de entrenamiento correspondientes.

La prueba antigua de 400 registros no sirve como evidencia independiente. Sus 100 potenciadores fuertes ya aparecen en entrenamiento. Quitarlos deja la prueba sin clase fuerte. Comparar coincidencias exactas tampoco demuestra independencia frente a secuencias relacionadas. Los hallazgos de solapamiento documentados detallan estas limitaciones.

Las características publicadas también se seleccionaron usando este conjunto. Mantenerlas fijas es apropiado para reconstruir la configuración publicada, pero no constituye una estimación nueva y totalmente independiente del proceso completo de selección. Los resultados de ambas vías deben presentarse por separado. Referencia de validación cruzada y evaluación por grupos.

Paso 06 / Especificación de implementación

Convertir cada secuencia en 4,105 números

El extractor está implementado y comprobado frente a las ecuaciones y el suplemento, con las decisiones pendientes sobre el código original documentadas. PseKNC combina frecuencias de palabras de ADN con descriptores estructurales calculados a partir de la secuencia. No son mediciones de cromatina ni de bucles de ADN.

Interpretación registrada: la desviación estándar muestral reproduce los valores normalizados de S2 dentro del redondeo a dos decimales (diferencia máxima 0.004724). La reconstrucción principal usa ventanas solapadas de 6 letras y pares de dinucleótidos por posición. Cuatro variantes adicionales conservan alternativas de recuento, tabla redondeada y normalización poblacional; ninguna se ha seleccionado por exactitud del modelo.

python -m unittest discover -s replication/ienhancer_2l -p "test_*.py" -v
python replication/ienhancer_2l/build_features.py --prepared replication/ienhancer_2l/output --receipts replication/ienhancer_2l/checkpoints/2026-10-13-groups-features/reference_receipts.json --output replication/ienhancer_2l/output/groups-features

El comando reutiliza comprobantes de referencia guardados para repetir el cálculo sin conexión. Escribe particiones, auditorías y cinco variantes de matrices comprimidas: 2,968 × 4,105 para la capa I y 1,484 × 4,105 para la capa II. Convenciones exactas, validación, campos de salida y comandos para consultar de nuevo la referencia →. Este comando no entrena clasificadores.

  1. Transcribir las seis columnas de S2: Rise, Roll, Shift, Slide, Tilt, Twist, para los 16 dinucleótidos. Conservar nombres, orden y origen. Verificar la normalización de los 16 valores de cada propiedad con la ecuación 9. Comparar con la tabla normalizada y redondeada de S2 y registrar la convención de desviación estándar y la precisión.
  2. Contar las 4,096 palabras posibles de 6 letras de ADN en un orden fijo y normalizar los recuentos. Registrar el paso entre ventanas y el tratamiento de los extremos.
  3. Para cada distancia j = 1…9, calcular la diferencia cuadrática media entre las seis propiedades normalizadas de pares de dinucleótidos, siguiendo las ecuaciones 7–8.
  4. Combinar esos nueve términos de correlación con las 4,096 frecuencias mediante la ecuación 6. Usar w = 0.1 para la capa I y w = 0.4 para la capa II. Ambas usan k = 6 y λ = 9 (ecuación 13).
El cálculo, en notación compacta
C(i, i+j) = media de 6 propiedades de (P(D_i) - P(D_(i+j)))²
theta[j] = suma de C(i, i+j), i=1…L-j-1, dividida por (L-j-1)
Z = suma(frecuencias) + w * suma(theta)
características = [frecuencia / Z, …, w * theta[j] / Z, …]

L es la longitud; D_i es el dinucleótido indexado en la posición i; P es una propiedad normalizada. La notación sigue las ecuaciones 6–8, sujeta a la comprobación de índices que se indica abajo.

Resolver antes de llamarlo reproducción exacta: el texto junto a la ecuación 6 y la leyenda de la Figura 2 dicen “non-overlapping”, mientras que el denominador L − j − 1 usa índices por posición. Recuperar una implementación de los autores o vectores de referencia para resolver el paso entre ventanas y los índices. También hay que resolver si se usaron valores redondeados de S2 o una normalización recalculada, y cualquier escalado posterior. Si no se recupera el original, registrar explícitamente la interpretación; no elegirla simplemente porque produzca una puntuación mayor.

Comprobaciones de aceptación: cada vector debe tener 4,105 valores finitos y no negativos, cuya suma sea aproximadamente 1 según la ecuación 6. Las pruebas deben incluir una secuencia de una sola base repetida (diferencias estructurales nulas), un ejemplo corto calculado a mano y ambos pesos. También deben verificar que el orden conserve la correspondencia con las etiquetas. La normalización de propiedades se hace sobre la tabla fija; un escalador adicional del modelo, si se usa, debe ajustarse solo con entrenamiento.

Paso 07 / Implementación del modelo

Entrenar dos clasificadores SVM separados

  1. Capa I: se utilizan las 2,968 filas. Positivo = potenciador (fuerte o débil); negativo = no potenciador. Las características se calculan con w = 0.1.
  2. Capa II: se utilizan únicamente los 1,484 potenciadores conocidos. Positivo = fuerte; negativo = débil. Las características se calculan con w = 0.4.
  3. Usar una SVM con núcleo RBF y registrar explícitamente C, gamma, escalado, pesos de clases, tolerancia del optimizador, reducción de variables (shrinking), versión de software y orientación de la puntuación. El artículo describe una búsqueda en cuadrícula, pero estos materiales no contienen los valores finales de C/gamma. gamma="scale" de scikit-learn no es una configuración recuperada del artículo.
  4. Buscar parámetros con validación limitada al entrenamiento. Para un intento de reconstrucción, registrar previamente una búsqueda logarítmica de C/gamma y todas las decisiones, sin ajustar usando etiquetas de prueba final ni intentar alcanzar repetidamente la Tabla 1. Una evaluación anidada más estricta debe mantener toda selección dentro de cada partición externa de entrenamiento.
  5. Guardar el identificador, etiqueta real, predicción, puntuación continua y partición de cada ejemplo reservado. Para una secuencia nueva, ejecutar la capa II solo si la I predice potenciador. Evaluar la tarea de la capa II del artículo sobre potenciadores conocidos por separado de esta cascada completa.

El núcleo RBF mide la similitud entre vectores de características. C controla la penalización de errores de entrenamiento; gamma controla el alcance local de esa similitud. Sus valores cambian las predicciones y deben registrarse.

Comprobación inicial: verificar dimensiones, etiquetas y signos de puntuación con un subconjunto de depuración, cuyo rendimiento no debe publicarse como resultado del estudio. Después corresponde ejecutar el protocolo completo definido previamente. Las matrices de características y las asignaciones de evaluación ya están disponibles. Falta implementar el flujo de entrenamiento y definir su búsqueda de parámetros, por lo que aún no hay un comando de entrenamiento ni resultados del modelo.

Calcular sensibilidad, especificidad, exactitud, MCC y área bajo la curva ROC con predicciones de ejemplos reservados y la clase positiva declarada. El AUC necesita puntuaciones continuas, no etiquetas predichas. Para la evaluación nueva, añadir AUPRC y estimaciones de incertidumbre que respeten los grupos. Incluir referencias basadas solo en GC y en frecuencias ordinarias de k-mers, con el mismo protocolo.

  • Archivar hashes de entrada, versiones de software, commit, valores/orden de la tabla de características, configuración, grupos/particiones, predicciones, métricas y tiempo de ejecución.
  • Separar los números publicados, los resultados de reconstrucción y los de una evaluación modificada. Una discrepancia es evidencia útil para explicar, no una razón para ocultar cambios de procesamiento.
  • La descripción “método reconstruido” corresponde cuando la implementación esté verificada. La descripción “resultados numéricos reproducidos” corresponde solo cuando el protocolo comparable, las decisiones de implementación y una tolerancia declarada previamente lo justifiquen. Los parámetros que faltan deben seguir visibles.

Hito: otra persona puede volver a ejecutar la configuración guardada y recuperar nuestras matrices y predicciones. Coincidir con una sola exactitud redondeada no demuestra una reproducción fiel.

Paso 09 / Conexión experimental posterior

Después conectar el modelo reconstruido con lentiMPRA

Una vez documentada la reconstrucción, la comparación experimental principal se basará en Agarwal, Inoue y colaboradores (Nature, 2025). La colección necesaria es NEW_2026_DATA/02_LENTIMPRA_ENCODE_2025, no todos los recursos nuevos.

  1. Leer los 60,000 diseños de constructos de la Tabla S10. Verificar el adaptador documentado de 15 bases en cada extremo de la secuencia de 230 bases antes de extraer el inserto de 200 bases. No recortar automáticamente archivos con otra definición de secuencia.
  2. Asociar los identificadores con mediciones en HepG2, K562 y WTC11. Utilizar los archivos combinados de ENCODE o sus réplicas, sin concatenar ambas representaciones de las mismas mediciones.
  3. Rastrear normalización, agregación de réplicas y cobertura. Ya recuperamos los 55,977 constructos de la tabla de especificidad; la reproducción numérica de sus puntuaciones sigue pendiente.
  4. Fijar el modelo reconstruido y su procesamiento. Excluir coincidencias con entrenamiento, incluidas K562_peak65192 y HepG2_DNasePeakNoPromoter39999, y revisar complementos inversos, similitud y regiones compartidas. Confirmar qué diseños superan los filtros de medición.
  5. Definir previamente las variables a evaluar en cada célula; comparar puntuaciones continuas con la actividad medida apropiada. Las etiquetas históricas fuerte/débil no equivalen a actividad alta/baja de reportero. Reentrenar con esas mediciones es otro análisis con su propia separación de entrenamiento y prueba.
