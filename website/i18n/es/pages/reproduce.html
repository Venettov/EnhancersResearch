De los archivos originales a un análisis reproducible

Sí, puedes usar VS Code. Es el espacio donde editas archivos y ejecutas comandos; Python realiza los cálculos. Nuestra primera tarea es reconstruir los dos clasificadores de iEnhancer-2L y documentar cuánto logramos reproducir del artículo.

Disponible ahora: el artículo, suplementos, secuencias, etiquetas recuperadas y un script probado para preparar los datos.
Pendiente de implementar: extracción de características, entrenamiento y evaluación. Los pasos siguientes son un plan de trabajo, no una afirmación de que ya reprodujimos la exactitud publicada.
  1. Preparar los datos
  2. Reconstruir el método
  3. Comprobar los resultados
  4. Conectar con lentiMPRA

Se trata de reproducción computacional usando el conjunto de referencia recibido. Reconstruir el muestreo original del genoma o repetir experimentos de laboratorio es otra tarea. No necesitas los 51.07 GB de recursos nuevos para comenzar.

Paso 01 / Herramientas

Preparar un espacio de investigación sencillo

VS Code + extensión Python de Microsoft
Permiten editar scripts, leer resultados y usar Terminal → New Terminal. El editor es opcional; los mismos comandos funcionan en tu terminal habitual.
Python
Usa una versión de Python 3 con soporte; Python 3.13 es una opción inicial sugerida para un entorno nuevo. El script de preparación solo requiere módulos integrados y Python 3.10 o posterior.
Git
Permite obtener el repositorio y registrar la versión exacta del código de cada ejecución.
NumPy, pandas, scikit-learn, matplotlib
Para la implementación posterior: matrices numéricas, tablas, clasificadores/métricas y figuras. Los cuadernos Jupyter son opcionales para explorar; conserva el flujo final en scripts.
LIBSVM
El artículo utilizó LIBSVM con un núcleo RBF. Compara su implementación oficial con SVC de scikit-learn, basado en LIBSVM, solo después de igualar explícitamente la configuración; los valores predeterminados no demuestran equivalencia.

Equipo: comienza con la CPU de una computadora portátil; no se requiere GPU ni un servicio de nube de pago para preparar datos o iniciar la reconstrucción con SVM. Las búsquedas completas de parámetros y la evaluación dejando un ejemplo fuera pueden llevar bastante tiempo. Empieza con una comprobación pequeña y mide la duración antes de ampliar la ejecución.

Paso 03 / Entorno

Un entorno virtual es un espacio de instalación de Python específico del proyecto. Esta es una propuesta moderna, no el entorno de software de 2015 recuperado de los autores. Los comandos usan Python 3.13; selecciona esa versión al instalar Python.

Puedes ejecutar el Paso 04 sin instalar nada más. Cuando comiences a implementar el modelo, instala las herramientas científicas en este entorno activo:

Usa python -m pip install libsvm-official si comparas la interfaz oficial de LIBSVM. Instalar paquetes e importarlos correctamente no valida el modelo. Guarda las versiones instaladas después de configurar el entorno; no actualices paquetes sin registrarlo durante un intento de reproducción.

Paso 04 / Ejecutable ahora

Preparar y comprobar las secuencias etiquetadas

Ejecuta el script de preparación. Compara hashes de archivos con las copias revisadas, lee FASTA, comprueba secuencias de 200 bases A/C/G/T, asocia etiquetas y mide coincidencias exactas entre prueba y entrenamiento. Conserva intactos los originales.

python replication/ienhancer_2l/prepare_data.py
python -m pip freeze > replication/ienhancer_2l/output/environment-lock.txt
git rev-parse HEAD > replication/ienhancer_2l/output/repository-commit.txt
python --version > replication/ienhancer_2l/output/python-version.txt

Comprobación esperada: 2,968 secuencias: 742 fuertes, 742 débiles y 1,484 no potenciadores. Prueba histórica: 400 registros, con 100 coincidencias exactas con entrenamiento, todas fuertes. Esto confirma únicamente la preparación de los datos.

  • benchmark.csv: secuencias, hashes, páginas de origen y etiquetas. is_enhancer vale 1 para fuerte/débil y 0 para no potenciadores. is_strong vale 1 para fuerte, 0 para débil y queda vacío para no potenciadores.
  • legacy_test_diagnostic_only.csv: la prueba histórica posterior, con una marca de solapamiento; no la combines con el conjunto de referencia.
  • data_audit.json: recuentos, hashes y límites. Los resultados quedan en replication/ienhancer_2l/output/, excluida de Git por defecto. Volver a ejecutar reemplaza estos archivos derivados; archiva una ejecución antes de cambiar los datos de entrada.
Si un comando falla

Python no encontrado: instala el intérprete seleccionado y vuelve a abrir la terminal. Archivo no encontrado: abre la raíz del repositorio y verifica que estén los datos versionados. Hash o etiqueta diferentes: detente y compara con los originales guardados en Git; no cambies los hashes esperados solo para superar la comprobación. Error de importación posterior: verifica que VS Code y pip usen el mismo entorno.

Paso 05 / Diseño de evaluación

Definir qué significará cada resultado antes de entrenar

Una partición es una parte de los datos que se reserva mientras el modelo aprende del resto. En la validación anidada, las particiones internas seleccionan parámetros y las externas estiman el rendimiento con ejemplos no usados en esa selección.

Vía A: reconstrucción histórica. Usa los 2,968 ejemplos de S1 para identificar potenciadores y sus 1,484 potenciadores para clasificar fuerza. El artículo seleccionó parámetros de características mediante validación cruzada de 5 particiones y después presentó resultados jackknife (dejando un ejemplo fuera). Una evaluación con parámetros fijos requiere 2,968 + 1,484 ajustes; la búsqueda de parámetros añade más. Una prueba rápida de 5 particiones sirve para depurar, no reproduce el resultado jackknife.

Vía B: una nueva evaluación independiente. Agrupa duplicados exactos, complementos inversos, secuencias similares y regiones solapadas antes de asignar particiones. Verifica el ensamblaje del genoma antes de usar las coordenadas de los encabezados. Conserva los grupos juntos; ajusta escaladores y parámetros solo en las particiones de entrenamiento. Reserva las externas para evaluar. Un diseño posible del proyecto es usar 5 particiones externas, 3 internas y semilla 42, si cada partición conserva suficientes grupos de cada clase. Son parámetros propuestos, no recuperados del artículo. Guarda las asignaciones concretas.

La prueba antigua de 400 registros no sirve como evidencia independiente. Sus 100 potenciadores fuertes ya aparecen en entrenamiento. Quitarlos deja la prueba sin clase fuerte. Comparar coincidencias exactas tampoco demuestra independencia frente a secuencias relacionadas. Consulta los hallazgos de solapamiento documentados.

Las características publicadas también se seleccionaron usando este conjunto. Mantenerlas fijas es apropiado para reconstruir la configuración publicada, pero no constituye una estimación nueva y totalmente independiente del proceso completo de selección. Presenta ambas vías por separado. Referencia de validación cruzada y evaluación por grupos.

Paso 06 / Especificación de implementación

Convertir cada secuencia en 4,105 números

Este es el código de extracción de características que todavía debemos escribir y verificar. PseKNC combina frecuencias de palabras de ADN con descriptores estructurales calculados a partir de la secuencia. No son mediciones de cromatina ni de bucles de ADN.

  1. Transcribe las seis columnas de S2: Rise, Roll, Shift, Slide, Tilt, Twist, para los 16 dinucleótidos. Conserva nombres, orden y origen. Verifica la normalización de los 16 valores de cada propiedad con la ecuación 9. Compara con la tabla normalizada y redondeada de S2 y registra la convención de desviación estándar y la precisión.
  2. Cuenta las 4,096 palabras posibles de 6 letras de ADN en un orden fijo y normaliza los recuentos. Registra el paso entre ventanas y el tratamiento de los extremos.
  3. Para cada distancia j = 1…9, calcula la diferencia cuadrática media entre las seis propiedades normalizadas de pares de dinucleótidos, siguiendo las ecuaciones 7–8.
  4. Combina esos nueve términos de correlación con las 4,096 frecuencias mediante la ecuación 6. Usa w = 0.1 para la capa I y w = 0.4 para la capa II. Ambas usan k = 6 y λ = 9 (ecuación 13).
El cálculo, en notación compacta
C(i, i+j) = media de 6 propiedades de (P(D_i) - P(D_(i+j)))²
theta[j] = suma de C(i, i+j), i=1…L-j-1, dividida por (L-j-1)
Z = suma(frecuencias) + w * suma(theta)
características = [frecuencia / Z, …, w * theta[j] / Z, …]

L es la longitud; D_i es el dinucleótido indexado en la posición i; P es una propiedad normalizada. La notación sigue las ecuaciones 6–8, sujeta a la comprobación de índices que se indica abajo.

Resolver antes de llamarlo reproducción exacta: el texto junto a la ecuación 6 y la leyenda de la Figura 2 dicen “non-overlapping”, mientras que el denominador L − j − 1 usa índices por posición. Recuperar una implementación de los autores o vectores de referencia para resolver el paso entre ventanas y los índices. También hay que resolver si se usaron valores redondeados de S2 o una normalización recalculada, y cualquier escalado posterior. Si no se recupera el original, registrar explícitamente la interpretación; no elegirla simplemente porque produzca una puntuación mayor.

Comprobaciones de aceptación: cada vector debe tener 4,105 valores finitos y no negativos, cuya suma sea aproximadamente 1 según la ecuación 6. Prueba una secuencia de una sola base repetida (diferencias estructurales nulas), un ejemplo corto calculado a mano y ambos pesos. Verifica que el orden conserve la correspondencia con las etiquetas. La normalización de propiedades se hace sobre la tabla fija; un escalador adicional del modelo, si se usa, debe ajustarse solo con entrenamiento.

Paso 07 / Implementación del modelo

Entrenar dos clasificadores SVM separados

  1. Capa I: usa las 2,968 filas. Positivo = potenciador (fuerte o débil); negativo = no potenciador. Calcula las características con w = 0.1.
  2. Capa II: usa únicamente los 1,484 potenciadores conocidos. Positivo = fuerte; negativo = débil. Calcula las características con w = 0.4.
  3. Usa una SVM con núcleo RBF y registra explícitamente C, gamma, escalado, pesos de clases, tolerancia del optimizador, reducción de variables (shrinking), versión de software y orientación de la puntuación. El artículo describe una búsqueda en cuadrícula, pero estos materiales no contienen los valores finales de C/gamma. gamma="scale" de scikit-learn no es una configuración recuperada del artículo.
  4. Busca parámetros con validación limitada al entrenamiento. Para un intento de reconstrucción, registra previamente una búsqueda logarítmica de C/gamma y todas las decisiones; no ajustes usando etiquetas de prueba final ni intentes alcanzar repetidamente la Tabla 1. Una evaluación anidada más estricta debe mantener toda selección dentro de cada partición externa de entrenamiento.
  5. Guarda el identificador, etiqueta real, predicción, puntuación continua y partición de cada ejemplo reservado. Para una secuencia nueva, ejecuta la capa II solo si la I predice potenciador. Evalúa la tarea de la capa II del artículo sobre potenciadores conocidos por separado de esta cascada completa.

El núcleo RBF mide la similitud entre vectores de características. C controla la penalización de errores de entrenamiento; gamma controla el alcance local de esa similitud. Sus valores cambian las predicciones y deben registrarse.

Comienza con algo pequeño: verifica dimensiones, etiquetas y signos de puntuación con un subconjunto de depuración. No publiques su rendimiento. Después ejecuta el protocolo completo definido previamente. Todavía no ofrecemos un comando de entrenamiento porque falta implementar y verificar el extractor de características y el flujo de entrenamiento.

Calcula sensibilidad, especificidad, exactitud, MCC y área bajo la curva ROC con predicciones de ejemplos reservados y la clase positiva declarada. El AUC necesita puntuaciones continuas, no etiquetas predichas. Para la evaluación nueva, añade AUPRC y estimaciones de incertidumbre que respeten los grupos. Incluye referencias basadas solo en GC y en frecuencias ordinarias de k-mers, con el mismo protocolo.

  • Archiva hashes de entrada, versiones de software, commit, valores/orden de la tabla de características, configuración, grupos/particiones, predicciones, métricas y tiempo de ejecución.
  • Separa los números publicados, los resultados de reconstrucción y los de una evaluación modificada. Una discrepancia es evidencia útil para explicar, no una razón para ocultar cambios de procesamiento.
  • Indica “método reconstruido” cuando la implementación esté verificada. Indica “resultados numéricos reproducidos” solo cuando el protocolo comparable, las decisiones de implementación y una tolerancia declarada previamente lo justifiquen. Los parámetros que faltan deben seguir visibles.

Hito: otra persona puede volver a ejecutar la configuración guardada y recuperar nuestras matrices y predicciones. Coincidir con una sola exactitud redondeada no demuestra una reproducción fiel.

Paso 09 / Conexión experimental posterior

Después conectar el modelo reconstruido con lentiMPRA

Una vez documentada la reconstrucción, utiliza Agarwal, Inoue y colaboradores (Nature, 2025) como comparación experimental principal. La colección necesaria es NEW_2026_DATA/02_LENTIMPRA_ENCODE_2025, no todos los recursos nuevos.

  1. Lee los 60,000 diseños de constructos de la Tabla S10. Verifica el adaptador documentado de 15 bases en cada extremo de la secuencia de 230 bases antes de extraer el inserto de 200 bases. No recortes automáticamente archivos con otra definición de secuencia.
  2. Asocia los identificadores con mediciones en HepG2, K562 y WTC11. Utiliza los archivos combinados de ENCODE o sus réplicas; no concatenes ambas representaciones de las mismas mediciones.
  3. Rastrea normalización, agregación de réplicas y cobertura. Ya recuperamos los 55,977 constructos de la tabla de especificidad; la reproducción numérica de sus puntuaciones sigue pendiente.
  4. Fija el modelo reconstruido y su procesamiento. Excluye coincidencias con entrenamiento, incluidas K562_peak65192 y HepG2_DNasePeakNoPromoter39999, y revisa complementos inversos, similitud y regiones compartidas. Confirma qué diseños superan los filtros de medición.
  5. Define previamente las variables a evaluar en cada célula; compara puntuaciones continuas con la actividad medida apropiada. Las etiquetas históricas fuerte/débil no equivalen a actividad alta/baja de reportero. Reentrenar con esas mediciones es otro análisis con su propia separación de entrenamiento y prueba.
